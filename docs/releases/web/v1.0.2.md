### 更新摘要

- 首次部署现在可以自动创建 D1 等 Cloudflare 资源，并在资源可用后完成数据库初始化。
- 部署与迁移增加安全重试、结果校验和清晰错误信息，减少临时故障导致的部署失败。

### 改进

- `npm run deploy` 统一负责迁移检查、首次资源创建和 Worker 发布，命名环境及配置参数会
  同时传给迁移和发布步骤。
- 网络中断、限流和 Cloudflare 临时服务故障最多重试五次，并采用退避间隔和随机延迟。
- 首次设置页的部署检查样式随首屏直接加载，“重新检查”按钮使用统一的次级按钮样式，
  补齐悬停、按下、键盘焦点和减少动态效果状态。

### 修复

- 修复首次部署中 D1 迁移早于自动资源创建执行，导致数据库无法初始化的问题。
- 修复远端迁移已成功但响应丢失后可能重复执行 SQL 的风险；重试前会重新读取迁移记录。
- 修复 Wrangler JSON 错误只写入标准输出时，日志仅显示退出码而丢失具体原因的问题。
- 修复首次设置页依赖登录后异步样式包，导致部署检查和“重新检查”按钮显示为浏览器默认
  样式的问题。

### 安全

- 部署日志会隐藏环境中的令牌、Secret、密码、凭据密钥、认证头和签名 URL 参数。
- 迁移文件名和 Wrangler 返回的迁移记录会进行格式校验；权限、配置和 SQL 错误不会被
  当作临时故障反复执行。

### 升级说明

- Web `1.0.1` 可直接升级，无需新增 D1 迁移、Worker 变量、Secret、资源绑定或 API 调整。
- Cloudflare Workers Builds 的 Deploy command 请使用 `npm run deploy`。已有推荐配置无需
  修改；若手动配置为 `npx wrangler deploy`，需改为项目部署命令后重新部署。
- 本次只发布 OmniMail Web `1.0.2`；OmniMail Float 和 Android 使用独立版本号，不受影响。

### 测试

- 通过部署脚本单元测试、D1 本地连续迁移、类型检查、Lint、生产构建和 Wrangler dry-run。
- 在全新 Cloudflare 账号完成真实首次部署：自动创建 D1、两个 R2 存储桶和邮件队列，
  执行并校验 34 个迁移；再次部署能跳过全部已完成迁移。
- 线上首页、`/api/health` 和 `/api/config` 均返回 HTTP 200，数据库、存储和队列检查通过。
- 首次设置页已在本地与 Cloudflare 测试站完成暗色主题视觉检查。
